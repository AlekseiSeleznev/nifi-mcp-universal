# Проверка обновления от 4 октября 2026 года

## Задание

Сверить проект с принятым upstream, полностью проверить код, исправить
подтверждённые ошибки, развернуть проверенную сборку локально и на сервере
LUVE, повторить проверки после развёртывания, затем слить в `main` и отправить
в GitHub. Проверить Windows-установку и чистоту рабочих каталогов.
Дополнение пользователя: сертификаты и их пароли должны сохраняться после
перезагрузки и использоваться как MCP, так и dashboard.

База проверки: `bddc24dc6fbfc1d4690d11d054207e6421f4de07`.
Источник и его актуальная ревизия: [upstream.md](upstream.md).

## Подтверждённые исправления

- Windows installer проверяет коды возврата Docker Compose, Codex и настройки
  автозапуска; ошибка готовности завершает установку с ошибкой.
- PowerShell smoke checks прекращаются при ошибке внешней команды.
- Windows Compose использует стандартную сеть при сборке образа.
- `test_nifi_connection` проверяет сохранённые подключения по имени, включая
  сертификаты; временная HTTP-сессия закрывается и при ошибке проверки.
- Временные PEM-файлы удаляются при закрытии сессии и при ошибке настройки
  сертификата; сырые исключения backend не записываются в журналы gateway.
- Dashboard проверяет сертификат в отдельном файле: неудачная замена не
  перезаписывает рабочий сертификат. Откат сохраняет прежний пароль и не
  показывает успешное подключение, если восстановление подключения не удалось.
- Открытие редактора сертификата и смена способа авторизации сохраняют выбранную
  проверку TLS. Ранее dashboard незаметно отключал её; ошибка воспроизведена
  в настоящем браузере и покрыта регрессионными сценариями.
- Происхождение заимствованных модулей и лицензия входят в репозиторий и образ.

## Развёртывание и реальные подключения

Один проверенный образ установлен локально и на LUVE. При передаче на сервер
проверены SHA-256 архива образа и Git-пакета; старые образы оставлены для отката.

- `/health`, `/dashboard`, `/dashboard/docs`, `/api/status`, `/api/connections`
  отвечают `200` на обоих узлах. На LUVE защищённые endpoints без Bearer token
  возвращают `401`.
- Через MCP проверены инициализация, схемы 67 инструментов, 5 prompts,
  переключение профилей, проверка сертификата, версия, корневая группа,
  процессоры, соединения, типы процессоров, controller services и parameter contexts.
- Успешны три локальных профиля к NiFi 2.8/2.11 и оба профиля LUVE к NiFi 2.11.
  Число регистраций и их режимы доступа сохранены: шесть локально, две на LUVE.
- Три последовательные проверки сертификата каждого рабочего профиля не
  оставляют временных PEM-ключей и сертификатов.
- На локальном рабочем dashboard проверены открытие редактора, сохранение
  трёх профилей без ввода сертификата/пароля и перезагрузка страницы.
  Параметры подключения сохраняются; ошибок JavaScript нет.

## Сохранение сертификатов и паролей

На обоих узлах включено `NIFI_MCP_PERSIST_SECRETS_IN_STATE=true`.
Сертификаты и состояние находятся в постоянном Docker volume; файл состояния
имеет права `0600`. В локальные рабочие профили возвращены пароли из уже
существовавших настроек соответствующих проектов после проверки сертификатов.
Секреты не включены в Git, образ или этот отчёт.

Оба рабочих контейнера пересозданы. Контрольная сумма файла состояния осталась
прежней, новые процессы подключились без повторного ввода учётных данных, а
MCP-проверки прошли повторно. Docker включён в автозапуск; у контейнеров
`restart: always`. Dashboard API скрывает сохранённый пароль как `***`.
Физическая перезагрузка компьютера и LUVE-сервера не выполнялась: проверены
пересоздание контейнера, постоянное хранилище и настройки запуска при загрузке.

## Ограничения

У трёх старых локальных регистраций уже отсутствовали необходимые данные:
у двух — файлы сертификатов, у одной — пароль. Их текущие MCP-пробы неуспешны.
Регистрации сохранены; для восстановления нужны исходные сертификаты/пароль.
Это отдельное состояние старых подключений, а не успешная проверка этих NiFi.

Проверки реальных NiFi выполняются чтением через MCP. Изменение потоков,
запуск процессоров и очистка очередей в эту работу не входят.
Настоящая установка контейнера в Docker Desktop на Windows не выполнялась;
границы CI-проверки описаны в [upstream.md](upstream.md).
Пользователь подтвердил, что для этой поставки достаточно Windows CI при
явном указании этого ограничения.
